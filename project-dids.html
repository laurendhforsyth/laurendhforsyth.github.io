Drowning In Dreams Studios

A work-in-progress website for a digital content studio, recreated from SquareSpace with HTML, CSS and JavaScript.

Project overview

Drowning In Dreams Studios (DIDS) is a company that I came up with several years ago to have a place to post video game tutorials and creation videos. DIDS creates digital content, YouTube videos, video game playthroughs and more.

The DIDS website is still a work in progress. It is coded using HTML, CSS and JavaScript and hosted using GitHub. The code editor used is Atom. The website was originally hosted using SquareSpace, but moved to a free hosting platform using code instead of a CMS.

Page and content organization

DIDS has a lot of content, so the website had to be organized appropriately in order to keep it easy to navigate. The main content is organized into the following categories:

  1. Gaming videos (YouTube)
  2. Video game development
  3. Art portfolio
  4. Blog
  5. Information about DIDS, including contact information and an about blurb

Since the content and design were being transferred from SquareSpace, I already had a good idea of what I wanted the website to look like. The main work was recreating it with front-end technologies, formatting the migrating content appropriately and making the website as accessible as possible. Having never worked on accessibility before, this last part was a challenge.

The plan

  1. Set up the project in GitHub and transfer over the domain name.
  2. Code a base page layout for new pages so they remain consistent:
    1. Theme
    2. Header
    3. Footer
    4. Base body content
    5. Stylesheet links for base styling
  3. Code the base stylesheet that provides styling for every page.
  4. Create the pages and link them together, updating and reusing the base layout for a complete navigation bar.
  5. Recreate pages using the base layout and copy the content over.
  6. Update stylesheets to ensure the pages look good at different screen sizes.
  7. Add accessibility code.

Current progress

Currently I am on step 5: recreating each page. I have completed the home and about pages and am currently working on the games page, including each game's subpages. Some content has already been written for those pages, but it needs updating, along with adding more images.

Troubleshooting

To troubleshoot publishing delays, I added a version number to the homepage that I update so I know when the live website has been updated.

One of the first issues I had was with the URLs that were created. As I own the domain drowningindreamsstudios.com, the subpages were a problem because of how GitHub displayed their URLs. GitHub does not automatically use the HTML file name as the URL; instead, it adds an additional path with the same name. For example, rather than drowningindreamsstudios.com/about, GitHub created drowningindreamsstudios.com/about/about.

To bypass this, I put each HTML file into its own folder. It is a bit less tidy on the backend, but it produces the URL I wanted. This also meant reworking the navigation bar links because every page was now in an additional folder. Once that was completed, everything worked and looked as expected.

Since DIDS is constantly being worked on, content needs to be updated frequently. My current issue is keeping on top of the ever-changing content workload.
